# 像素风视频skill

复用已经确认的前20秒室内像素视频语言及横竖封面。成果是实际可播放的视频和两张独立封面，不停在文案或分镜建议。

## 交付约定

默认最终交付恰好三项：

- `out/video.mp4`：横屏1920×1080、30fps、H.264/AAC。
- `out/cover-landscape.png`：横屏1920×1080。
- `out/cover-portrait.png`：竖屏1080×1920，独立构图。

封面不插进视频开头；视频直接进入第一段情节。不额外塞入卧室思考开场。源码、脚本、检查图保留工作目录，默认不作为额外交付项。用户明确要求其它尺寸、片长、文件或开场时按新要求调整。

## 接到一个新主题后

1. 用户给完整文案或镜头要求时，以其为准做可视化，不另编一个替代故事。只有主题时，自行写适合主题的短文案、心声与3–5个具体场景；默认约20–30秒，按可读性自然安排，不为了凑时长拉慢镜头。无需重新询问已经确定的画风与交付方式。
2. 阅读 [视频制作](references/video.md)，查看 [室内参考帧](assets/reference/indoor-contact.png)。必要时查看 [前20秒无声参考](assets/reference/front-20s-silent.mp4)。参考中的升学、失业、催婚、哭泣只是原案例；新主题必须替换事件、人物关系、道具和文字。
3. 使用自带工程起步，或在用户已有工程原位修改。运行 `python3 <本skill目录>/scripts/bootstrap.py <新工程绝对路径> --theme '新主题'`。工程自带像素场景、角色、道具转场、横竖封面和字体，运行依赖不指向原聊天工作区。读 [工程适配](references/project.md)，完成主题改写后再出片。
4. 默认固定像素镜位，用表情、动作、气泡累积和道具转场推进；不以全画面缩放或抖动表现压力。统一源帧时钟驱动场景、人物、字幕、气泡；变速时同步改变段落长度、字幕和转场落点。
5. 读 [横竖封面](references/covers.md)，分别排版。大标题、小像素人物、思考框和递减圆点是默认视觉层级。标题与新主题对应，不能沿用案例标题，也不能把横图裁成竖图。
6. 用户指定音乐时沿用其要求；未指定时可用脚本生成轻柔的原创像素配乐。不要默认沿用原案例的B站音乐。默认没有旁白；人物心声是可读气泡。配乐一般保持原速原调，场景变速不等于整条音乐变速。
7. 渲染三件成果，按下述标准检查。只有用户要求先看demo时才先交demo；否则完成三件成果再交付。

## 必须保留的制作特征

- 横片640×360逻辑画布→整数3倍输出；竖封面360×640→整数3倍。Canvas关闭平滑，CSS `imageRendering: pixelated`；纹理固定种子，画面随同一帧可重现。
- 温暖米色、木色与青绿/蓝灰；家具和道具细致，主角轮廓清晰。像素字体、硬边框、硬阴影保持统一；底部两行旁白与人物头顶心声分层。
- 主角身份连续，局部手势与脸部表演明确。压力场景用旧气泡保留、新气泡逐个加入、边框逐渐转暖；安静场景用单一心声。不把指责与哭泣强加给所有主题。
- 转场由当前场景中的实际道具发起，在中点完整遮住画面后揭示下一场；首尾不闪黑、不露旧镜头。场景本身不随遮挡物缩放。

## 验收与交付

先运行 `npm run lint`，再导出关键帧：第一句、气泡最密处、情绪峰值、每个转场中点、最后字幕。检查人物脸/手、文字完整、层级和安全区；变速后再检查心声、字幕及拟音是否跟随。

两张封面分别检查原尺寸与缩略图：标题一眼可读，人物小而清晰，思考圆点与头部不相碰，竖图无裁切。用 `ffprobe` 核实视频帧率、尺寸、帧数和音轨；无爆音、无意外长静音。不得仅通过静态海报就宣称视频完成。

最终回复简短说明完成、实际片长，嵌入视频并给横封面和竖封面链接。保留旧版以方便继续调整；不自动发布到外部平台。
