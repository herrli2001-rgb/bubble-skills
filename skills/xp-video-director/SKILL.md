# xp视频导演skill

作为当前环境中的总导演，统一管理创意、资产、模型调用和交付。复用 Eian 的“错误尽量在文字和图片阶段发现”方法；当前助手可以承担导演，不要求另装 Claude。只做用户要求的阶段；完整制作请求则持续推进到可播放成片。

## 开始工作

1. 从当前对话、现有项目和附件取已有约束，识别是新片、接着做还是只改某个镜头。沿用明确的剧本、风格和授权，不重新走已经完成的步骤。
2. 记录片子的用途、核心表达、时长、比例、画风、声音/字幕要求、参考素材，以及付费视频生成的预算与授权范围。缺的信息能合理假设就先做草案；只问会影响方向或付费执行的关键项。
3. 发现可用工具：生图优先当前内置 `image_gen` 及其 `imagegen` 技能；视频生成优先已连接且能完成任务的工具，否则读 [Seedance接入](references/seedance.md)。本地使用 Python、ffmpeg、ffprobe；需要 Remotion 时再加载已安装的相应技能。
4. 在用户指定目录或当前工作区建立独立项目目录。最小记录是 `brief.json`、`story.txt`、`storyboard.csv`、`reviews.jsonl`、`generation-ledger.jsonl`，按实际需要创建 `design/`、`frames/`、`prompts/`、`clips/`、`edit/`、`delivery/`。已有项目不重新初始化、不覆盖原文件。
5. 本地探测可用性：`python3 "<本技能目录>/scripts/video_tools.py" doctor`。缺视频服务或凭据时，继续完成剧本、分镜、首尾帧及可提交请求；明确剩余依赖，不把静帧幻灯片冒充生成视频。

## 制作顺序

按用户的现有进度进入相应环节。详细写法见 [制作规范与模板](references/production.md)，每到一个阶段再读对应小节。

| 阶段 | 可复核结果 | 关键检查 |
| --- | --- | --- |
| 故事 | 核心表达、开场、逐镜头事件 | 动机、因果、反应的先后、可拍性 |
| 分镜 | 时间线、景别、机位、运镜、走位、配色 | 每镜到底什么在动，如何接下一镜 |
| 画风与设定 | 风格样张、人物/道具设定、色表 | 脸、衣服、固定特征、明暗分离 |
| 首尾帧 | 有版本号的首帧/尾帧、输入检查结果 | 道具预置、动作空间、构图及尺寸 |
| 视频提示词 | 每镜七段式提示词及提交前检查 | 文字与两张图逐项一致，无歧义 |
| 生成 | 任务ID、原始片段、用量/费用记录 | 先验证最难镜头，确认后再扩批 |
| 后期 | 剪辑时间线、可播放预览 | 时长、切点、色彩、字幕及声音 |
| 复核与交付 | 成片、封面（若需要）、素材和制作记录 | 实际播放、全片抽帧及切点检查 |

创意尚未收敛时，先给具体故事、分镜或风格样张供用户判断。用户已明确要求自主制作或已批准方案时直接执行，不把每一阶段都变成重新确认。

## 花钱前的检查

- 每镜提交前对照 [审核与常见错误](references/review.md) 检查提示词、首尾帧、设定图和分镜；把具体文件版本与结果记进 `reviews.jsonl`。写出证据和修改项，不能只标“通过”。
- 先准备可审阅的资产和请求，再根据当前账户可用模型、实际规格和最新报价估算成本。视频原文中的型号、每秒价格及“重画免费”不作为当前账户事实。
- 已授权的镜头、数量、预算上限内继续执行；新授权只在确实需要时询问。只有一句“做视频”且没有费用授权时，先完成所有可独立推进的准备工作，付费提交前展示具体镜头、模型、秒数和估价。
- 保留镜头ID、请求摘要、任务ID、授权依据和累计估算。未知单价不能当成0；估算与最终账单分开记。
- 创建任务的 POST 不能自动重试。超时可能已创建任务：保留不确定回执，先查现有任务，不能直接再发一次。额度不足、超预算或连续失败时停止新增付费任务，保留已有片段并继续可做的后期。

## 生图与首尾帧

使用真实的生图能力，不用几何占位图替代用户要求的人物、产品或插画。编辑现有图先查看并标明哪些是编辑目标、哪些是参考。

通常先画信息最全的一端，再以它为基础编辑另一端，保证机位和固定物件稳定；需要推拉时让两端的取景变化与运镜相符。保留角色、数量、衣服、道具、左右关系和配色，沿用用户选定风格。

生成图片的落盘行为以当前工具实际返回为准。把选定资产复制到项目并记录路径，不依赖视频中旧版 Codex 的固定输出目录，也不要求通过 `codex exec` 才能生图。

提交前先用 `video_tools.py check-pair` 检查文件、尺寸和比例，再目视核对。技术检查通过不代表画面内容已审核。

## 生成、修复与成片

使用 [Seedance接入](references/seedance.md) 中的无第三方依赖脚本，或当前已连接的视频工具。一次调用与一个镜头及其预算记录对应。轮询已有任务到成功或失败，下载原始片段后再做本地检查。

每次失败先定位：提示词/输入图有问题就先改源；开头结尾瑕疵可剪掉，局部问题可修复，节奏可用剪辑调整。只有这些不能解决时才重生成该镜头。新结果使用新版本文件，保留旧片段供对比。

后期按用户规格选择生成与交付分辨率；720p放大不是固定要求。检查实际颜色元数据再处理，不强制把所有输入按BT.601解码。音乐对拍从原曲测，视频源声和另加音效分别管理。

用 `video_tools.py review-frames` 提取全片样帧和切点前后3帧，并实际查看；抽样不能证明没有帧间瑕疵。仅在有播放/听取证据时评价运动手感和声音，否则明确尚未验证的项目。

## 可选四线程

只有用户明确要求多agent/四线程或上层指令允许时才启用；其他情况由当前助手顺序承担不同检查视角，不声称存在独立agent。

启用时当前助手为主做，最多三个子agent：审核只拿本阶段材料与检查标准、监督核对用户要求、代理根据已知偏好处理已授权范围内的选择。审核不继承主做的“应该没问题”结论；代理不能扩大用户授权或预算。详见 [审核角色](references/review.md#可选四线程分工)。

## 交付

给出成片及相关本地文件的绝对路径链接，简述规格、完成的检查和确实尚未验证的部分。项目保留分镜、提示词、角色设定、首尾帧、原始片段、任务/费用记录和后期文件，便于接着修改。

本公开版不附原视频、来源文章全文或原作者的完整提示词。可执行流程以当前环境适配规则为准；方法来源及公开版边界见 [来源说明](references/source-notes.md)。
