# 审核与常见错误

## 每阶段的证据

审核记录建议用以下JSON结构逐行追加到项目的 `reviews.jsonl`：

```json
{
  "stage": "pre-submit",
  "shot_id": "S001",
  "files": [],
  "result": "needs-fix",
  "findings": [],
  "checked": [],
  "not_checked": []
}
```

实际填写明确的文件版本、发现的问题和检查过什么。`pass`、`needs-fix`、`not-checked`表达本次实际结果；不确定的地方写明不确定。

故事审核只拿定稿故事和需求，先复述看到的故事，再追问因果、现实或世界观逻辑、开场吸引力与反应顺序。不要先给审核者主做的自信结论。

首尾帧/提交前审核拿：分镜、提示词、首帧、尾帧、角色/道具设定、色表。

1. 放大看图，再缩到目标播放大小：角色、手、脸、文字与远景主体是否可辨。
2. 逐句核对提示词与画面的位置、左右、人数、数量、衣服、表情和光线。
3. 两端的镜头位置、取景、固定背景与色彩是否按分镜一致；有变化是否有剧情原因。
4. 动作的道具是否预置，起点、路径、终点和手的位置是否明确，留白与头顶是否够。
5. 尾帧的推拉、焦点或位置变化是否能让模型拍出指定运镜。
6. 技术检查：文件可读、方向正确、尺寸和比例相符；视频模型支持本次输入与参数。
7. 提交范围与预算是否仍在用户授权内；费用未知或超限不写“通过”。

## 原作者经验转为可检验问题

这是排错线索，不是对所有模型永久成立的事实。新任务按实际结果更新。

| 现象 | 先检查与修改 |
| --- | --- |
| 一群人同时做同一动作 | 写清先后，首帧姿势避免完全一致 |
| 本应由风造成的动作变成人手操作 | 写清物理原因与双手位置 |
| 云/月亮/植物意外长脸 | 换具体材质与形状描述，去掉易拟人化歧义 |
| 人走反方向 | 用画面左/右及明确地标写方向 |
| “窗户后面的老人”等被误解 | 写清是哪栋房子的哪个窗，不指望排除词消除歧义 |
| 道具数量变化 | 明确数量、颜色与状态变化的原因 |
| “不要出现”仍出现 | 改写为应存在的正面状态，再检查输入图 |
| 道具被自动赋予惯常用途 | 若叙事允许，改构图或移出道具；否则拆解动作验证 |
| 东西凭空出现 | 首帧预置，或写出清楚的入画来源 |
| 东西突然飞走/瞬移 | 明确动作路径、承接动作与终点 |
| 雨/帽子/纹身中途丢失 | 首尾帧都维持，核对设定与可见性 |
| 闪电过于写实 | 与画风一致地描述云中短暂亮光，检查可剪掉的异常头帧 |
| 单镜动作过多失控 | 简化为一到两个主要动作或拆镜头 |
| 动作时间偏差 | 留合理剪辑余量，后期变速或重排 |
| 运镜不足 | 检查首尾取景差异，必要时在后期做适度推拉 |
| 人物无意开口 | 对照声音与表情要求，可局部修复或改提示词 |
| 混入不需要的音乐 | 检查音频参数与实际音轨，必要时弃用源声另配 |
| 结尾突然跳到尾帧 | 检查最后数帧；可剪除或合理停帧 |
| 开头单帧锐度/颜色异常 | 对照首帧与相邻帧，检查可剪除的孤立坏帧 |
| 越到后面越暗/冷 | 对照源首帧检查漂色，局部校色而非盲目统一滤镜 |

## 可选四线程分工

只有本次任务允许多agent时使用。主做为当前助手，其他角色最多各一个子agent，遵守实际并发上限。

| 角色 | 输入与权限 | 输出 |
| --- | --- | --- |
| 主做 | 用户需求、工程、工具；付费受既有授权限制 | 创作、素材、版本、调用与合成 |
| 审核 | 本阶段必要材料，不附“预期通过”结论；只读 | 问题、证据、改法、通过/待改 |
| 监督 | 用户的需求与已作决定、当前结果；只读 | 遗漏、冲突和尚未满足的要求 |
| 代理 | 已明确的偏好、候选方案和预算；只读建议 | 已授权范围内的选择及依据 |

顺序通常是主做交审核，再交监督；有分歧再给代理比较。代理不能代替未给出的费用授权、用户创意定案或上层审批。没有子agent能力时采用顺序检查，不能把同一助手的第二遍检查包装成独立盲审。
