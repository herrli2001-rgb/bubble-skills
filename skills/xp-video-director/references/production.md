# 制作规范与模板

按正在做的阶段读取。没有交付某个文件格式的要求时，优先用易修改的JSON、CSV和纯文本。主导演维护同一套镜头ID，例如 `S001`，提示词、图片、任务和剪辑都沿用这个ID。

## 1. 故事

先写核心表达，再写开场与逐镜头事件。故事有明确的动机、阻碍、解决和结果；喜剧或需要群体反应时，把“问题→主角行动→旁人反应”分开，反应有自然先后。

每个转折追问：为什么这样？物件从哪里来？角色够得到吗？解决方式是否符合设定？幻想世界遵循自身规则，不强加现实题材逻辑。

片段式结构对独立镜头更稳，连续叙事则维护位置、道具、动作和光线的接续。按故事需要选择，不为了省事改掉用户明确的叙事结构。

人物交叉、手持细小物件、镜面倒影、左右不对称特征、一镜多个复杂动作等是需要提前拆解的难点；有这些要求时设计验证镜头，不直接删除用户要的内容。

## 2. 分镜与配色

`storyboard.csv` 推荐字段：

```text
shot_id,timeline_start,timeline_end,generation_seconds,purpose,shot_size,camera_position,camera_motion,blocking,visible_motion,expression,transition,palette,first_frame,last_frame,prompt_file,review_status,task_id,clip_file
```

- 时间线时长与模型生成时长分开。后者符合当前模型限制，按需要留少量剪辑余量；不要把整秒报价乘以剪辑后的秒数冒充实际计费。
- 走位明确按画面左/右、前/后写；谁入画、谁出画、经过什么物件一一对应。
- 写明摄影机、焦点、人物、光线或前景物件中谁在动；也允许有目的的静止、停顿及固定机位。
- 景别和机位服务叙事，有需要时混用俯拍、仰拍、背面、过肩与前景遮挡。“正面平视不超过两次”只是原作者的经验参考。
- 运镜有目的：跟随、揭示、强调或建立关系，不为动而动。
- 黄金比例约38%/62%可作为构图参考，居中、对称、留白等用户要求优先。
- 画第一张正式图前做分场色表；需要时用代码做色块草图和黑白预览，检查人物与背景的明暗分离。
- 有参考片时实际查看画面，记录观察到的景别、机位、入出画及节奏。不能把对参考的猜测当成测量结果。

## 3. 风格与设定

提取参考中可描述的线条、材质、光线、配色、形体和空间特点。先选定一张可复用风格样张；用户已有明确模板或风格资产时直接使用。

角色设定需要时包含正面、侧面和关键表情；固定道具说明比例、颜色、数量及持握方式。不对称特征明确在角色身体哪边，另注明镜头中的可见方向。

项目可维护 `design/bible.json`：

```json
{
  "style": "本片的可观察风格要素",
  "palette": {},
  "characters": [],
  "props": [],
  "locations": [],
  "continuity_rules": [],
  "reference_files": []
}
```

这里的空列表是结构示例，实际生产按已知素材填入，不把示例文本带进生成提示词。

## 4. 首尾帧

每镜先写清首帧、尾帧与中间变化，再生成图。先完成信息多、位置明确的一端，在同一资产上编辑另一端；同一机位尽量沿用原图。

动作会用到的杯子、帽子、雨、纹身等在两端都应按剧情存在；如果本来就要出现或消失，说明可见原因。人物反应预先在构图中留出位置、脸与动作空间。推近/拉远的首尾取景应有对应变化。

技术检查示例：

```bash
python3 "<本技能目录>/scripts/video_tools.py" check-pair \
  --first frames/S001-first-v001.png \
  --last frames/S001-last-v001.png --ratio 16:9
```

检查失败时先准备修正副本，不覆盖原资产。技术检查不代替看图，人物数量、表情、手、纹身、道具和风向仍需目视比对。

## 5. 七段式视频提示词

下列结构按镜头填充，去掉不需要的占位说明。时间段之和与生成秒数一致，动作通常聚焦一到两个主要变化。

```text
【画风】具体的线条、材质、光线和配色。全段人物设计与选定首尾帧一致。
【镜头】整段时长；景别；机位；明确的运镜或固定机位；是否一镜到底。
【构图与配色】人和物的位置、画面左右、前后层次、背景与光线颜色。
【人物】每个角色的外观、服装、固定特征和道具，沿用设定。
【逐秒】
起始短暂稳定在首帧。
按时间区间写谁做什么、动作原因、表情和双手位置、移动方向。
结束短暂稳定在尾帧。
【声音】现场能产生的声源；是否说话；音乐需求。音频参数同时在请求体明确设置。
【约束】人数、道具数量、脸与身形、场景和画风的一致性；有无字幕与水印。
```

起始0.2秒、末尾0.3秒是可用参考，不强制所有片子机械停顿；需要连续动作的镜头按节奏调整。优先写正面的状态和可见原因，避免只有长串“不要”。

只提供首帧的模型也可使用此结构，尾段写目标状态；不把未提供的尾帧当成模型已经收到的输入。

## 6. 生成与预算记录

先选一到两个最难的正式镜头验证新做法，成功资产计入成片。后续镜头可在已授权预算内继续，不重问已给出的允许范围。

`generation-ledger.jsonl` 每次提交记录镜头ID、版本、模型、规格、生成秒数、估价依据、费用上限、授权来源、请求摘要和任务ID；收到用量或账单后补独立记录。

模型支持的最短/最长时长、首尾帧能力、声音和分辨率以当前官方文档及账户实际能力为准。缺价格时先准备请求，再核实估价，不从原文数字推断当前费用。

如果提交结果不确定，不重复POST；查询任务、对照已保存回执和控制台。重拍先改变出错的提示词或输入帧，原样重复通常不能解决根因。

## 7. 后期

维护剪辑表：镜头ID、原片路径、入点/出点、时间线位置、变速、转场、源声与音乐。先剪通顺，再做颜色、字幕、声音和交付规格。

- 修复顺序由具体问题决定：可剪掉的头尾先剪，局部画面与嘴形问题可局部修复，运镜不足可考虑合理裁切推拉；严重形变或叙事错误再重生成。
- 音乐拍点从原始音轨测量。转场不能遮盖关键动作或让节奏拖长。
- 用ffprobe检查色彩、尺寸、帧率和音轨；元数据缺失时先用代表片段比较，不统一强制套用BT.601解码。
- 如需放大，可比较Lanczos与轻锐化后的预览，避免用过强锐化掩盖低清；不默认全片插帧。
- 用户要源文件时保留命令、时间线或工程文件；不用额外搭建与本片无关的编辑系统。

## 8. 全片复核与交付

先看实际成片，按观众视角写清看懂的故事和不清楚的地方，再核对约束。用全片样帧与切点前后各3帧检查突跳、颜色和道具变化：

```bash
python3 "<本技能目录>/scripts/video_tools.py" review-frames \
  delivery/final-v001.mp4 --out reviews/final-v001 \
  --fps 1 --cuts 5.2,10.8
```

查看生成的帧，不把“抽帧成功”写成“画面合格”。报告问题用时间、镜头/帧号、证据、严重程度和建议。声音与运动手感需要实际播放证据。

交付按任务需要包括成片、选定封面、字幕/音频文件、分镜、提示词和项目素材。复盘只保存可复用的观察与修复办法，不把某次模型失败升为永久禁令。
